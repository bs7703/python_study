1. 프로젝트 개요
본 프로젝트는 객체지향(OOP) 설계를 기반으로 한 CLI(명령줄) 퀴즈 게임입니다. 데이터(JSON)와 로직(Python)을 분리하고, 설정값(config)과 상수(constants)를 코드에서 분리하여 유지보수성을 높인 것이 특징입니다. 강력한 예외 처리를 통해 파일 손상 시에도 백업 데이터로 자동 복구됩니다.

2. 퀴즈 주제와 선정 이유
주제: 종합 상식 (천문, 예술, 과학, 지리, 역사, 프로그래밍)
선정 이유: 특정 분야에 치우치지 않는 다양한 데이터를 다룸으로써, 어떤 형식의 문항이든 처리할 수 있는 **범용적인 데이터 구조(스키마)**를 설계하고 검증(check_data)하는 연습을 하기 위함입니다.
3. 실행 방법
quiz_game.py, quiz.py, constants.py 파일과 JSON 파일들이 동일 경로에 있는지 확인합니다.
터미널에서 python quiz_game.py 를 입력하여 실행합니다.
프로그램은 우선 state.json(진행상황)을 로드하며, 파일이 없거나 손상 시 basic_data.json(기본값)으로 실행됩니다.
4. 기능 목록 (클래스 및 함수별 상세 설명)
🅰️ QuizGame 클래스 (quiz_game.py) - 게임 총괄 관리자
함수명	상세 기능 및 내부 로직
__init__	게임 초기화. config와 데이터를 로드하며, 2단계 예외처리(주 파일 실패 시 백업 파일 로드)로 안정성을 확보합니다.
run	프로그램의 메인 루프. 메뉴를 표시하고 입력을 받아 해당 기능(action)으로 연결하며, 강제 종료(Ctrl+C) 시 자동 저장을 시도합니다.
display_menu	config.json의 메뉴 정보를 읽어와 화면에 UI 형식으로 출력합니다.
advanced_input	숫자 입력 검증기. 지정된 범위(range) 내 정수만 받도록 강제하며, 잘못된 입력 시 재입력을 요구합니다.
advanced_strinput	문자열 입력 검증기. 정해진 길이(5~50자) 조건을 만족할 때까지 입력을 반복시킵니다.
solve_quiz	개별 문제 풀이 담당. 힌트 사용 여부에 따른 점수 차감 로직과 정답 채점을 처리합니다.
start_quiz	전체 퀴즈를 순회하며 solve_quiz를 호출하고, 최종 점수를 합산해 최고 점수를 갱신합니다.
set_basic_quiz	JSON의 딕셔너리 데이터를 실제 Quiz 객체(Object)로 변환하여 리스트로 만듭니다.
add_quiz	사용자로부터 새 문제 정보를 입력받아 유효성을 검증한 뒤 데이터에 추가합니다.
del_quiz	문제 목록을 보여주고 사용자가 선택한 번호의 문제를 삭제합니다.
load_quiz / save_quiz	퀴즈 데이터를 검증(check_data)하여 불러오거나, 현재 상태를 파일에 저장합니다.
check_data	데이터 유효성 검사기. 로드된 데이터가 리스트인지, 필수 키가 있는지, 값의 범위가 맞는지 검증하여 프로그램 오류를 사전 방지합니다.
load_data / save_data	실질적인 파일 입출력(I/O) 담당. FileNotFound, JSONDecode 등 상세 에러를 개별 처리합니다.
🅱️ Quiz 클래스 (quiz.py) - 개별 문제 설계도
함수명	상세 기능
show_quiz	문제와 4개의 선택지를 번호를 매겨 보기 좋게 문자열로 반환합니다.
show_hint	힌트가 존재할 경우에만 힌트를 반환합니다.
check_answers	사용자의 답과 정답을 비교해 배점(정답) 또는 음수 배점(오답)을 반환합니다.
get_explanation	문제의 해설을 반환합니다.
5. 파일 구조 (역할 및 관계 상세)
code
📋 복사
📁 Project Root
│
├── 🐍 quiz_game.py    # [핵심 로직] 게임 흐름 제어, 사용자 입출력, 파일 관리 (Controller)
├── 🐍 quiz.py         # [데이터 모델] 퀴즈 하나의 속성과 행동 정의 (Model)
├── 🐍 constants.py    # [설정/상수] 에러 메시지, 안내문, 규칙(길이/범위) 정의 (하드코딩 방지)
│
├── 📄 config.json     # [환경 설정] 게임 제목, 메뉴 항목, 점수 계수(factor) 등 '규칙' 저장
├── 📄 state.json      # [실행 데이터] 사용자가 플레이하며 변경되는 '현재 상태' 저장 (읽기+쓰기)
└── 📄 basic_data.json # [백업 데이터] 초기 원본 및 복구용 데이터 (주로 읽기 전용)
구조 설계 의도: 로직(.py)과 데이터(.json)를 철저히 분리했습니다. 이로 인해 코드를 수정하지 않고도 json 파일만 교체하면 퀴즈 내용이나 게임 규칙을 바꿀 수 있습니다.

6. 데이터 파일 설명 및 스키마 설계 의도
📌 config.json (게임 규칙 설정 파일)
게임의 동작 방식을 정의합니다.

menu_options: label(표시명)과 action(실행함수명)을 쌍으로 묶었습니다.
설계 의도: 파이썬의 getattr 기능과 연동하여, 메뉴가 추가되더라도 run 함수의 코드 수정 없이 JSON 데이터 추가만으로 기능이 확장되도록 설계했습니다. (확장성 극대화)
game_settings: answer_factor(정답계수), hint_factor(힌트계수) 등 점수 계산의 가중치를 저장하여 난이도 조절을 용이하게 했습니다.
📌 state.json / basic_data.json (퀴즈 데이터 파일)

json
{
  "best_score": 0,       // (Number) 최고 점수 저장
  "quizzes": [           // (Array) 퀴즈 묶음
    {
      "question": "...", // (String) 문제
      "choices": [...],  // (Array) 4개의 선택지
      "answer": 3,       // (Number) 정답 번호
      "answer_point": 2, // (Number) 배점
      "hint": "...",     // (String) 힌트
      "explanation": ".."// (String) 해설
    }
  ]
}
최상위 구조 (Dictionary)를 채택한 이유:
데이터를 단순히 퀴즈 리스트([...])로만 두지 않고, best_score와 quizzes를 포함하는 **딕셔너리({...})**로 감쌌습니다.
의도: 퀴즈 문제들뿐만 아니라 '최고 점수'라는 부가적인 메타데이터를 하나의 파일에서 함께 관리하기 위함입니다. 이를 통해 게임 상태 전체를 한 번의 저장/로드로 처리할 수 있습니다.
개별 퀴즈 구조 (Key-Value)를 채택한 이유:
문제 정보를 리스트(순서 의존적)가 아닌 딕셔너리(key: value)로 저장했습니다.
의도: data['answer'] 처럼 키(이름)로 데이터에 접근할 수 있어 코드의 가독성이 높고, 향후 항목 순서가 바뀌거나 새로운 정보(예: 난이도)가 추가되어도 안정적으로 동작합니다.

데이터 구조에 대한 설계 의도를 명확히 파악하고 계신 점이 인상적입니다. 특히 config.json의 action과 getattr를 연결한 부분은 **"데이터 주도 설계(Data-Driven Design)"**의 좋은 예시이니, README에 강조하시면 훌륭한 어필 포인트가 됩니다.
