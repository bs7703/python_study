
# 📝 Python Quiz Game Project (v1.0)

> **객체지향 설계와 데이터 중심 구조를 활용한 CLI 기반 퀴즈 프로그램**

본 프로젝트는 파이썬을 이용한 **객체지향(OOP)** 설계를 기반으로 한 CLI 퀴즈 게임입니다. 데이터(JSON)와 로직(Python)을 철저히 분리하고, 강력한 예외 처리를 통해 안정성을 확보한 것이 특징입니다.

개발주소:https://github.com/bs7703/python_study

## 🎯 퀴즈 주제 및 선정 이유
- **주제**: 종합 상식 (천문, 예술, 과학, 지리, 역사, 프로그래밍)
- **선정 이유**: 특정 분야에 치우치지 않는 다양한 데이터를 다룸으로써, 어떤 형식의 문항이든 처리할 수 있는 **범용적인 데이터 구조(스키마)**를 설계하고 이를 검증(`check_data`)하는 로직을 구현하기 위함입니다.

---

## 🚀 실행 방법

1. `quiz_game.py`, `quiz.py`, `constants.py` 및 JSON 파일들이 동일 경로에 있는지 확인합니다.
2. 터미널에서 아래 명령어를 입력합니다.
   ```bash
   python quiz_game.py
   ```
3. 프로그램은 우선 `state.json`(진행상황)을 로드하며, 파일이 없거나 손상 시 `basic_data.json`(기본값)으로 자동 복구됩니다.

## 🛠 기능 목록

### 1️⃣ QuizGame 클래스 (`quiz_game.py`)
| 함수명 | 상세 기능 및 내부 로직 |
| :--- | :--- |
| `__init__` | 게임 초기화. 설정과 데이터를 로드하며 2단계 예외처리를 통해 안정성 확보. |
| `run` | **메인 루프**. 메뉴 표시 및 입력에 따른 기능 연결, 종료 시 자동 저장 수행. |
| `display_menu` | `config.json` 정보를 읽어 UI 형식으로 메뉴 출력. |
| `advanced_input` | **숫자 입력 검증**. 지정된 범위 내 정수만 허용. |
| `advanced_strinput` | **문자열 입력 검증**. 정해진 길이(5~50자) 조건 검사. |
| `solve_quiz` | 개별 문제 풀이 담당. 힌트 사용 시 점수 차감 및 정답 채점 로직. |
| `start_quiz` | 전체 퀴즈 순회, 최종 점수 합산 및 최고 점수 갱신. |
| `set_basic_quiz` | JSON 딕셔너리 데이터를 `Quiz` 객체 리스트로 변환. |
| `add_quiz` / `del_quiz` | 퀴즈 항목의 동적 추가 및 삭제 기능. |
| `load_quiz` / `save_quiz` | 데이터 검증(`check_data`)을 거친 파일 입출력. |
| `check_data` | **데이터 유효성 검사**. 리스트 형식, 필수 키 존재 여부, 값의 범위 검증. |
| `load_data` / `save_data` | `FileNotFound`, `JSONDecode` 등 상세 에러 처리를 포함한 I/O 담당. |

### 2️⃣ Quiz 클래스 (`quiz.py`)
| 함수명 | 상세 기능 |
| :--- | :--- |
| `show_quiz` | 문제와 4개의 선택지를 번호와 함께 문자열로 반환. |
| `show_hint` | 힌트가 존재할 경우에만 해당 내용 반환. |

| `get_explanation` | 문제에 대한 상세 해설 반환. |

## 📂 파일 구조
```text
📁 Project Root
│
├── 🐍 quiz_game.py    # [핵심 로직] 게임 흐름 제어 및 파일 관리 (Controller)
├── 🐍 quiz.py         # [데이터 모델] 퀴즈 객체의 속성과 행동 정의 (Model)
├── 🐍 constants.py    # [설정/상수] 에러 메시지 및 규칙 정의
│
├── 📄 config.json     # [환경 설정] 메뉴 구성 및 게임 계수(Factor) 저장
├── 📄 state.json      # [실행 데이터] 현재 진행 상태 및 퀴즈 저장 (Read/Write)
└── 📄 basic_data.json # [백업 데이터] 초기 데이터 및 복구용 (Read Only)
```
> **설계 의도**: 로직과 데이터를 분리하여, 코드 수정 없이 JSON 파일 교체만으로 게임 내용과 규칙을 변경할 수 있는 **유지보수성**을 극대화했습니다.

## 📊 데이터 구조 및 설계 의도

### 📌 `config.json` (게임 규칙)
- **`menu_options`**: `label`과 `action`(함수명)을 쌍으로 구성.
  - **의도**: 파이썬의 `getattr`와 연동하여, 코드 수정 없이 JSON 수정만으로 메뉴를 확장할 수 있는 **데이터 주도 설계(Data-Driven Design)** 구현.
- **`game_settings`**: 배점 및 감점 계수를 관리하여 난이도 조절 용이성 확보.

### 📌 `state.json` (퀴즈 데이터)
```json
{
    "best_score": 0,
    "quizzes": [
        {
            "question": "문제 내용",
            "choices": ["보기1", "보기2", "보기3", "보기4"],
            "answer": 3,
            "answer_point": 2,
            "hint": "힌트 내용",
            "explanation": "해설 내용"
        }
    ]
}
```
- **최상위 딕셔너리 구조**: 퀴즈 리스트와 `best_score`를 한 곳에 담아 게임 상태 전체를 통합 관리.
- **개별 퀴즈 Key-Value 구조**: 순서에 의존하지 않고 키 이름으로 데이터에 접근하여 가독성을 높이고, 향후 데이터 항목 추가 시 하위 호환성 유지.

### 💡 학습 포인트
- **데이터 주도 설계**: `config.json`의 설정값에 따라 프로그램의 동작이 결정되도록 설계.
- **안정성**: `check_data`를 통한 런타임 에러 방지 및 2단계 백업 로드 시스템.
- **OOP 활용**: 퀴즈를 객체화하여 상태와 행위를 캡슐화.
